  <action>
Edit `frontend/src/components/BottomTabBar.tsx` to make the selected tab unambiguously distinct. Keep this scoped to the one file. Do NOT touch surrounding layout, do NOT add new files, do NOT add dependencies.

Required changes:

1. **Stronger contrast on selected vs unselected text/icon color.**
   - Selected: `text-ink-primary` (keep — full ink).
   - Unselected: change from `text-ink-primary/70` to `text-ink-tertiary`. Token `--color-ink-tertiary` is `#6B6B6B` dark / `#6E6E73` light — that is the intended "muted but legible" rung. The current `/70` arithmetic on ink-primary produces a near-white grey in dark mode that is indistinguishable from selected on a sunny iPhone screen.
   - Quick grep before edit: `grep -n "text-ink-tertiary\|bg-surface-elevated" frontend/src` — confirm these utility classes are already used elsewhere (they should be — Tailwind 4 picks tokens from `@theme`). If `bg-surface-elevated` is NOT already in use anywhere, fall back to inline style `style={{ backgroundColor: 'var(--color-surface-elevated)' }}` for the selected pill in step 2.

2. **Add a filled-pill background on the selected tab.**
   - Inside `tabClass`, when `isActive`, add `bg-surface-elevated` (or the inline-style fallback above). Keep the existing flex/size classes.
   - Add `rounded-xl mx-2 my-1.5` to give the pill clear edges inside the bar without breaking the 56px tap target. Apply to BOTH active and inactive (so inactive has the same geometry, just transparent bg) — this avoids layout shift on tab change.
   - Net result: selected tab reads as a solid raised pill against the bar, unselected reads as a flat icon at muted ink.

3. **Bolden the icon stroke gap.**
   - In `CameraLens`: bump `strokeWidth` active from `2.25` to `2.5`, inactive from `1.75` to `1.5`. Wider gap = clearer at-a-glance.
   - In `FeedIcon`: bump active `sw` from `1.5` to `2`, inactive from `1.25` to `1.25` (keep). Wider gap.
   - Do NOT change icon size or viewBox.

4. **A11y: emit `aria-current="page"` on the active link.**
   - `NavLink` from react-router-dom v6 supports passing `aria-current` directly; when truthy it's only applied when the link is active. Add `aria-current="page"` as a prop on both `<NavLink>` elements. Verify in DevTools that the inactive one does not carry the attribute (react-router strips it when inactive).
   - Keep the existing `aria-label="Camera"` and `aria-label="Feed"` — they label the destinations.
   - Keep the `aria-label="Primary"` on the `<nav>`.

5. **Do NOT change**: routes, `NavLink` `to` paths, `end` prop on the camera link, the safe-area padding, the fixed positioning, the `z-30`, or the `border-t border-hairline`.

Touch only this one file. The diff should be ≤ ~20 lines.
