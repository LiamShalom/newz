# Quick Task 260502-w52: Audio-on by default

## Goal

Feed and comment-popup videos should "default to audio on" without breaking iOS Safari autoplay. Literal `muted=false` initial state would cause iOS Safari to block autoplay entirely (per `muteBus.ts:3-6` and CLAUDE.md "iOS Safari is the primary surface" hard constraint). Approach: keep `muted=true` initial state so videos still autoplay muted on load, then auto-unmute on the first user gesture (tap/touch/key) — TikTok pattern. By the time the user perceives the feed, audio is on.

## Tasks

### 1. Add one-shot auto-unmute to `frontend/src/muteBus.ts`

- Export `armAutoUnmute()` — installs capture-phase listeners for `pointerdown`, `touchstart`, `keydown` on `window`.
- On first matching gesture: call `setMuted(false)` and remove all listeners (one-shot).
- If gesture target matches `[data-mute-control]`: disarm without flipping (let the dedicated mute button's onClick handle the toggle, no race).
- `setMuted()` also disarms — explicit caller wins; we never re-arm after the user has expressed a preference.
- SSR-safe: bails when `typeof window === "undefined"`.

### 2. Tag mute buttons with `data-mute-control`

- `frontend/src/components/SegmentCard.tsx` — feed mute toggle.
- `frontend/src/components/CommentPopup.tsx` — popup mute toggle.

### 3. Arm at app boot

- `frontend/src/main.tsx` — call `armAutoUnmute()` once before `createRoot`.

## Verify

- `npx tsc --noEmit` clean.
- iOS Safari: feed videos still autoplay muted on load, audio kicks in on first scroll/tap, mute button still toggles correctly when used as the first gesture.
