# Quick Task 260425-q06: Gate seed_demo_segment on OFFLINE_DEMO Summary

One-liner: Added an inline `OFFLINE_DEMO` env-var gate at the top of `seed_demo_segment()` so production deploys (where the env var is unset) no longer auto-insert a stub segment that 404s on `/media/demo-clip-1.webm`, while preserving the Tier-5 WiFi-dies staged-replay path under `OFFLINE_DEMO=true`.

## Behavioral Change

Single-file change in `backend/seed/demo_segment.py`:

1. Added `import os` to the imports block.
2. Updated the module docstring to note the gating contract.
3. Updated the function docstring to note the gate.
4. Inserted a 3-line gate as the first statement of `seed_demo_segment()`:

   ```python
   if os.environ.get("OFFLINE_DEMO", "").lower() != "true":
       log.info("seed_demo_segment skipped (OFFLINE_DEMO not enabled)")
       return
   ```

The caller in `backend/app.py:73-74` (`from .seed.demo_segment import seed_demo_segment` / `await seed_demo_segment()`) is unchanged — the gate lives inside the function, not at the call site. This preserves transparency for `unittest.mock.patch("backend.seed.demo_segment.seed_demo_segment", new_callable=AsyncMock)` used in `backend/tests/test_feed_segments.py:76,110`.

## Why Inline `os.environ.get` Instead of `from ..config import OFFLINE_DEMO`

`backend/config.py:9` defines `OFFLINE_DEMO = os.environ.get("OFFLINE_DEMO", "false").lower() == "true"` at module-import time. That captured value is stale once tests monkeypatch the env mid-run. The inline pattern at `backend/app.py:46` evaluates the env at call time, which is the established convention for runtime gates in this codebase (`_pre_warm_sdk`). Following the same convention here keeps the gate test-friendly and consistent.
