# Quick Task 260502-c55 — Summary

## What changed

`frontend/src/components/SegmentCard.tsx`

- Added `captionRef`, `captionExpanded`, `captionOverflows` state.
- `useEffect` + `ResizeObserver` measures `scrollHeight > clientHeight + 1` against the rendered caption `<p>` so we know whether the caption actually exceeds 2 lines under the current viewport. Re-runs on `segment.caption` and `captionExpanded` changes.
- Caption `<p>` now applies Tailwind 4's built-in `line-clamp-2` when `!captionExpanded`. When expanded, the clamp is removed so the full text shows.
- A small "Read more" / "Show less" toggle button renders below the paragraph **only** when overflow is detected (or while currently expanded). Styled `text-[12px] text-ink-secondary hover:text-ink-primary` to match the existing muted-link pattern.

## Why

The story (caption) under each card was rendering full-length, blowing the card layout for long captions and pushing the action row way down the page. Two-line clamp + opt-in expand keeps the feed scannable, matches the pattern users expect from social feeds, and only pays the cost of the toggle when there's something to expand.

## Verification

- `npx tsc --noEmit -p tsconfig.json` clean.
- Toggle appears only when caption exceeds 2 rendered lines (overflow measurement).
- Click expands → "Show less" → click collapses back to 2 lines.
- ResizeObserver re-measures on viewport resize, so a 3-line caption that becomes 1-line after a wide-window resize will correctly hide the toggle.

## Notes

- No new dependencies. Tailwind 4 ships `line-clamp-*` utilities natively.
- Toggle is a plain `<button type="button">` so it stays keyboard-focusable for free.
- The h2 title above the caption is unchanged (still uses `segment.title || segment.caption` as a heading); only the long-form story paragraph at line 259 is clamped.
