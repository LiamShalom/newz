# Quick Task 260425-pw1: Add anthropic dependency to backend requirements

## Problem

`backend/pipeline/caption_pipeline.py:116` does `import anthropic` to call `AsyncAnthropic` for vision-grounded captions. `backend/requirements.txt` only declared `claude-agent-sdk==0.1.68`. Locally the import resolved because `anthropic-0.97.0` was present transitively in the dev `.venv`. On Railway the import fails inside the `try` block and every compiled segment falls back to the generic caption — the vision-grounded Claude path is dead in prod.

SDK pre-warm succeeded, so `ANTHROPIC_API_KEY` IS set on Railway. The only missing piece is the package manifest.

## Fix

Add `anthropic>=0.39.0` to `backend/requirements.txt` immediately after `claude-agent-sdk==0.1.68`.

- **Constraint choice:** `>=0.39.0` (not pinned). This matches the surface used in `caption_pipeline.py` (`AsyncAnthropic`, async `messages.create` with vision parts) and avoids forcing a lock-step bump every time the SDK ships. Pin only if the prod-side breakage repeats.
- **Do not** rely on transitive availability via `claude-agent-sdk==0.1.68` — `anthropic` is not a declared dep of that SDK version.

## Verification

Fresh Python 3.11 venv, install the full `backend/requirements.txt`, then:

```python
import anthropic
from anthropic import AsyncAnthropic
import claude_agent_sdk
```

Expected: `anthropic` resolves to a version `>=0.39.0`; `AsyncAnthropic` imports; `claude_agent_sdk` still installs cleanly (no resolver conflict).

Result: `anthropic 0.97.0`, `AsyncAnthropic OK`, `claude_agent_sdk OK`.
