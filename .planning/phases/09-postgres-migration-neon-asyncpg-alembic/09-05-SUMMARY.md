## Decisions Made

- **Migration revision id is a stable string literal (`0001_initial_v1_1_schema`), not a hash.** Phases 10-12 reference this as `down_revision = '0001_initial_v1_1_schema'` and the explicit name avoids the rebase headaches that come with autogenerated revision hashes.
- **Filename prefix uses D-22's `YYYYMMDD_` timestamp (`20260428_`) — matches the `file_template` in alembic.ini exactly.** Future migrations use the same convention so chronological ordering matches commit order.
- **`is_hidden BOOLEAN NOT NULL DEFAULT FALSE` (not nullable).** A later `ALTER COLUMN ... SET NOT NULL` triggers a Postgres table rewrite on a non-empty table; landing it NOT NULL with a default at table-creation time is free. Phase 11 just flips values, no schema work.
- **`moderation_decisions` and `reports` ship with only PK + FK + `created_at TIMESTAMPTZ DEFAULT NOW()`.** D-04 Hybrid says Phase 9 lands the table+FK; Phase 11/12 own the rest of the column shape. Adding the `created_at` column now is harmless (every row will have it anyway).
- **`reported_csam.content_preserved_until TIMESTAMPTZ NOT NULL` with NO encoded duration.** Per RESEARCH Pitfall 2 the post-2024 REPORT-Act amendment to 18 U.S.C. § 2258A sets a 1-year minimum (the REQUIREMENTS.md figure is stale). The migration is silent on retention; Phase 11's writer chooses the duration. The migration's docstring + the table comment flag the staleness for the user-owed REQUIREMENTS reconciliation before Phase 11 ships.
