# Phase 1 — UI Design Contract

> Visual and interaction contract for Phase 1 (Foundation, Capture & Ingest). Generated by gsd-ui-researcher from CONTEXT.md decisions D-01..D-08 + REQUIREMENTS.md FND/CAP/ING. Verified by gsd-ui-checker.

**Phase scope reminder:** iPhone Safari camera capture + clip upload + raw feed playback. **Throwaway feed** (~30-60min budget); Phase 4 rebuilds with TikTok-style autoplay + AI segments. **No AI in this phase.** Demo target is a 60-second 4-clip walk-through on a real iPhone — not a production app.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (greenfield Phase 1; shadcn deferred to Phase 4 when real feed UI lands) |
| Preset | not applicable |
| Component library | none (plain React + Tailwind 4 utility classes; capture UI is full-screen custom — buttons, ring, modal hand-rolled) |
| Icon library | `lucide-react` (only 4 icons needed Phase 1: `X`, `RefreshCcw` for camera-flip, `Camera`, `MapPin`) |
| Font | system stack (`-apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`) — zero-cost, native feel on iOS Safari, no font-loading FOIT |

**Why no shadcn in Phase 1:** Per CONTEXT.md D-08, the Phase 1 feed is explicitly throwaway. The capture flow is full-screen custom (camera viewport, ring-fill record button, gating modal, retake/submit overlay) — shadcn primitives don't apply. Reintroduce shadcn at Phase 4 when the real feed lands with reusable cards, overlays, and badges (FED-03).

**iOS Safari constraints baked into the contract:**
- All interactive surfaces must be safe-area-inset-aware (`env(safe-area-inset-bottom)` for FAB; `env(safe-area-inset-top)` for X dismiss).
- All viewport-locked screens (camera, retake) use `100dvh` not `100vh` to handle Safari's address-bar collapse.
- Tap targets >= 44x44 CSS px (Apple HIG minimum).

## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gap |
| sm | 8px | Compact element spacing (badge padding, tile gap) |
| md | 16px | Default element spacing (modal body padding, feed tile gap) |
| lg | 24px | Section padding (modal padding, screen edge inset) |
| xl | 32px | Major layout gaps (between feed header and first tile) |
| 2xl | 48px | Reserved (likely unused in Phase 1) |
| 3xl | 64px | Reserved (likely unused in Phase 1) |

**Exceptions:**
- **Record FAB diameter: 72px** (outer ring 80px) — TikTok/Instagram-scale red record button per CONTEXT.md D-01. Single exception; does not propagate.
- **Tap target floor: 44px** (Apple HIG) for all icon-only controls (X dismiss, camera-flip toggle). Achieved via 24px icon + 10px padding on each side.
- **Bottom safe-area inset:** FAB anchored at `bottom: calc(16px + env(safe-area-inset-bottom))` to clear iOS Safari's bottom toolbar (CONTEXT.md D-01 documents the conflict; mitigation here).

## Typography

3 sizes, 2 weights — minimal because Phase 1 has almost no text content (one modal, one feed empty state, one error screen, relative timestamps).

| Role | Size | Weight | Line Height | Where Used |
|------|------|--------|-------------|------------|
| Body | 16px | 400 | 1.5 | Modal body copy, error copy, empty-state hint |
| Label | 14px | 400 | 1.4 | Relative timestamps on feed tiles ("4 min ago"), button labels |
| Heading | 24px | 600 | 1.2 | Modal title ("Allow camera & location"), error screen heading |

**Two weights total:** 400 (regular) and 600 (semibold). No 500/700 in Phase 1.

**Not declared:** Display size — Phase 1 has no hero/marketing surface.

## Color

App is **dark-first** to match the camera-app mental model (a camera viewport is dark; switching from a light feed to a dark camera causes flash). Single theme. No light mode in Phase 1.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0A0A0A` (near-black) | Page background, camera viewport letterbox, feed background |
| Secondary (30%) | `#1A1A1A` (elevated surface) | Feed tile background, modal surface, retake-screen overlay scrim |
| Accent (10%) | `#EF4444` (red-500) | Record FAB fill, recording-ring fill, primary Post-clip button fill |
| Destructive | `#EF4444` (red-500) | **Same as accent** — Phase 1 has no destructive actions distinct from primary record/post; merging keeps the palette to 3 colors |
| Foreground primary | `#FAFAFA` (off-white) | Body text, icons on dark background |
| Foreground muted | `#A3A3A3` (neutral-400) | Relative timestamps, empty-state hint text |
| Border | `#262626` (neutral-800) | Tile dividers, modal border (1px hairline) |

**Accent (red `#EF4444`) reserved for — explicit list, no exceptions:**

1. Record FAB on feed (filled circle)
2. Recording-progress ring around stop button (fill animates over 30s)
3. Post-clip button on retake screen (filled pill)
4. Allow-and-continue button on priming modal (filled pill — same red, primes the user that this is the "go" path)
5. Error-state heading icon (camera-blocked screen) — drawn as an outlined icon with red stroke, not red fill

**Accent NOT used for:** body links, focus rings (use `#FAFAFA` 2px outline instead), feed tile interactions, X dismiss icon (white), camera-flip icon (white), pull-to-refresh indicator.

**Why red for both primary AND destructive:** Phase 1 has no destructive actions in the strict sense (no "Delete clip" — the X is implicit retake, not a destroy). Reusing red avoids introducing a second semantic color (e.g. orange/amber) that would carry no meaning. Phase 4 may need to split this if a delete/report action lands.

**60/30/10 audit:**
- Camera screen: ~95% black (live preview itself fills viewport) + accent FAB ring + white icons. Compliant.
- Feed screen: ~60% black background, ~30% tile surface (#1A1A1A), ~10% red FAB. Compliant.
- Retake screen: ~60% video pixels (full-bleed) + ~30% bottom-gradient scrim + ~10% red Post-clip. Compliant.

## Copywriting Contract

Voice: **direct, lowercase-friendly, zero marketing fluff, plain English**. No exclamation marks. No emoji. The product is anonymous — never reference "you" as if there's an account.

| Element | Copy |
|---------|------|
| Primary CTA (record FAB) | (icon-only — no label; the red circle IS the CTA per CONTEXT.md D-01) |
| Priming modal title | `Allow camera and location` |
| Priming modal body | `Newz needs your camera to record and your location to group clips by event. Nothing is tied to you — there's no account.` |
| Priming modal primary button | `Allow and continue` |
| Priming modal secondary | (none — modal is gating per D-02; only Allow-and-continue exits it. Browser back / OS back closes it.) |
| Recording stop button | (icon-only — square stop glyph inside the progress ring) |
| Retake screen dismiss (X) | (icon-only — top-left X; tooltip-equivalent aria-label `Retake`) |
| Retake screen primary | `Post clip` |
| Feed empty state heading | `No clips yet` |
| Feed empty state body | `Tap the red button to record one.` |
| Feed tile timestamp | `{n} min ago` / `{n} sec ago` / `just now` (uses `Intl.RelativeTimeFormat`) |
| Feed pull-to-refresh hint | (system default — no custom copy) |
| Error: camera permission denied | Heading: `Camera blocked` · Body: `Open Settings → Safari → Camera and allow access for this site, then return and tap the red button again.` · Action: `Open Settings` link (deep-link `prefs:root=Safari` if iOS supports; else inert with the manual instruction shown) |
| Error: location permission denied | Heading: `Location blocked` · Body: `Newz groups clips by where they were recorded. Open Settings → Safari → Location and allow access, then return and tap the red button again.` · Action: same as camera-blocked |
| Error: location unavailable / timeout | Heading: `Couldn't get your location` · Body: `Step outside or near a window and try again. Indoor GPS is unreliable.` · Action: `Try again` button |
| Error: upload failed (transient) | Heading: (no heading — toast-style) · Body: `Saved. We'll retry when you're back online.` (per CAP-09 localStorage queue; no scary error language for the queued case) |
| Error: recording exceeded 30s | (silent — recording auto-stops at 30s and transitions to retake screen; no error copy needed per CONTEXT.md D-03 "30s hard cap is enforced silently") |

**Destructive confirmations:** None in Phase 1. The X on retake is intentionally not a confirm-required destructive — that would add friction to the core capture loop and the user hasn't committed anything yet (clip exists only in browser memory). Merge a confirm in Phase 4+ if a "delete published clip" action ever lands.

## Interaction Contract

Phase-1-specific interaction rules executor must follow:

1. **No skeleton loaders.** If a screen has data-loading state >300ms, show nothing (black background) — Phase 1 has no API calls slow enough to need skeletons. Camera initialization shows the live preview as soon as `getUserMedia` resolves; no loading copy.
2. **No spinners on primary buttons.** Post-clip button shows `submitting` state by going to 60% opacity for the duration of the POST (which returns 202 in <100ms per ING-02 — effectively imperceptible).
3. **No toast library.** The single toast case (CAP-09 queued upload) uses a self-rolled bottom-of-screen 3-second auto-dismiss div. No `react-hot-toast` / `sonner` dependency in Phase 1.
4. **No animations beyond:** (a) ring-fill on record button (CSS `stroke-dashoffset` transition over 30s linear); (b) modal fade-in/out (200ms opacity transition). No spring physics, no Framer Motion in Phase 1.
5. **Modal dismiss behavior:** Priming modal is gating per D-02 — there is no backdrop tap-to-dismiss and no Escape key (we're on iOS Safari, no keyboard). Allow-and-continue is the only exit.
6. **Pull-to-refresh:** Feed uses native iOS Safari pull-to-refresh (no custom indicator). Manual refetch on navigate-back-from-camera per CONTEXT.md D-08.
7. **Focus management:** When PrimingModal opens, focus moves to Allow-and-continue button. When RetakeScreen mounts, no autofocus (the video starts playing; focus stays where the OS puts it).
8. **All `<video>` elements must have `playsinline`** — without it, iOS Safari opens the native fullscreen player and breaks the feed UX. This is a load-bearing attribute.
