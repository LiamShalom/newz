# Phase 8: Observability Scaffolding - Research

**Researched:** 2026-04-28
**Domain:** Python observability — structured logging (structlog), error tracking (Sentry), metrics (Prometheus), FastAPI middleware
**Confidence:** HIGH (all 3 core libraries verified against Context7 + PyPI within last 30 days; FastAPI middleware contextvars landmine confirmed via 5+ sources)

## Summary

Phase 8 installs four observability primitives — structlog→stdlib bridge, Sentry with PII scrubber, Prometheus `/metrics`, and an XFF-strip middleware — all gated by env vars so OFFLINE_DEMO=true makes zero outbound calls. The bridge approach (D-01) is the right call: 70 existing `log = logging.getLogger(__name__)` callsites across 12 backend files keep working unchanged because `structlog.stdlib.ProcessorFormatter` rewires stdlib logging records through structlog's processor chain inside a `dictConfig()` formatter.

The single biggest landmine: **FastAPI's `BaseHTTPMiddleware` runs `dispatch()` in a sub-task whose context is isolated from the route handler's context** — `bind_contextvars()` calls inside `BaseHTTPMiddleware.dispatch` do NOT propagate to the endpoint, breaking PRIV-02 silently. Fix: implement `RequestIDAndContextvarsBind` and `XFFStrip` as **pure ASGI middleware** (an `__init__(self, app)` + `__call__(self, scope, receive, send)` class), not `BaseHTTPMiddleware` subclasses. This is non-negotiable.

Secondary gotchas: `request.url.path` (raw, with IDs) vs `request.scope["route"].path` (templated) for the Prometheus `route` label; processor-chain ordering inside `ProcessorFormatter`; `sentry_sdk.init(dsn="")` behavior in 2.x (a no-op since 2.0, but explicit `if SENTRY_DSN:` guard is safer).

**Primary recommendation:** Land observability in this order across one wave: `observability/__init__.py` (logging dictConfig + Sentry init) → `observability/middleware.py` (XFFStrip + RequestIDAndContextvarsBind, both pure-ASGI) → `observability/metrics.py` (Counters/Histograms as module globals) → `observability/anonymity.py` (sha256 helper) → wire into `backend/app.py` with the observability import at line 1, before any other backend import.

### Locked Decisions

**Logger Migration Strategy**
- **D-01:** Bridge structlog to stdlib via `structlog.stdlib.ProcessorFormatter`. All 70 existing `log = logging.getLogger(__name__)` call sites emit JSON automatically through structlog's processor chain — zero call-site rewrites in this phase.
- **D-02:** The processor chain MUST include `structlog.contextvars.merge_contextvars` so that bridged stdlib calls pick up the per-request bound contextvars (`request_id`, `session_hash`, `clip_id`).
- **D-03:** No native structlog kv-style call sites in this phase. Pipeline hot-path conversion is deferred — adopt opportunistically when those files are touched in Phases 9-13.

**Renderer Toggle**
- **D-04:** `LOG_FORMAT` env var, values `json | console`, default `json`. Prod (Railway) leaves it unset → JSON. Local dev sets `LOG_FORMAT=console` in `backend/.env`.
- **D-05:** Read `LOG_FORMAT` once at logger configuration time. No runtime toggle.

**session_hash Strategy**
- **D-06:** `session_hash = sha256(session_uuid).hexdigest()`. Constant across all time. No HMAC, no key rotation.

- **D-08:** Single helper, e.g. `def session_hash(uuid: str) -> str` in `backend/observability/anonymity.py`. Pure function, no state.

**/metrics Endpoint Auth**
- **D-09:** `GET /metrics` is `ADMIN_TOKEN`-guarded using the same auth pattern as `POST /admin/reset`. Empty `ADMIN_TOKEN` → 503.
- **D-10:** Authenticated callers receive standard Prometheus text format. Bearer token / header scheme matches `/admin/reset` exactly.

### Pattern 1: structlog → stdlib Bridge via ProcessorFormatter

**What:** A single `dictConfig()` setup where the `formatters` block uses `structlog.stdlib.ProcessorFormatter`. Stdlib `logging.getLogger(__name__).info("msg")` and `structlog.get_logger().info("event", k=v)` both flow through the same processor chain and emit identical JSON.

**When to use:** This phase. Lets us add JSON + contextvars without rewriting 70 callsites.

**Code:** see Code Examples §1.

### Pattern 2: Pure ASGI Middleware (NOT BaseHTTPMiddleware)

**What:** A class with `__init__(self, app)` and `async def __call__(self, scope, receive, send)`. No `dispatch()`, no `BaseHTTPMiddleware`. The class wraps the next app in the stack and forwards the ASGI three-tuple.

**When to use:** Whenever the middleware needs to (a) mutate `scope` (XFF strip), or (b) bind contextvars that the route handler must see (PRIV-02). The structlog/FastAPI community has a known landmine here — `BaseHTTPMiddleware.dispatch` runs in a sub-task whose `contextvars.Context` is isolated from the route handler's. `bind_contextvars()` calls inside `dispatch` silently disappear by the time the handler runs.

**Code:** see Code Examples §3, §4.

### Pattern 3: try/finally Clear Contextvars

**What:** Every request must `clear_contextvars()` BEFORE binding (defensive, in case prior request leaked) and AGAIN in `finally:` (so a partially-bound failed request doesn't leak into the next).

**When to use:** Always. With single-worker asyncio, two requests can interleave on the same event loop; `contextvars` are per-Task so this is mostly defensive — but `merge_contextvars` looks at the current Task's context, and a leaked bind across awaits inside an exception path would surface in the wrong log line.

**Code:** see Code Examples §3.

### Pattern 4: Module-Level Histogram/Counter Globals

**What:** Define `REQUEST_DURATION = Histogram(...)` and `REQUEST_COUNT = Counter(...)` once at module import, in `observability/metrics.py`. Reuse via `.labels(...).observe(...)` and `.labels(...).inc()`. Defining these inside a function recreates them per-call → `ValueError: Duplicated timeseries in CollectorRegistry`.

**When to use:** Always — this is the prometheus-client canonical pattern.

### Pattern 5: Route Template (not raw URL) for `route` Label

**What:** Read `request.scope.get("route").path` for the `route` label, NOT `request.url.path`. The former gives `/clips/{clip_id}` (template), the latter gives `/clips/abc-123-def-456` (raw, with the clip_id baked in → cardinality explosion).

**Subtle:** `request.scope["route"]` may not be populated in all contexts (e.g., a 404 before routing resolves). Guard with `.get("route")` and fall back to `"<unmatched>"` or skip the metric entirely. Prometheus instrumentator libraries default to grouping unmatched requests under a `none` handler or excluding them.

### Anti-Patterns to Avoid

- **`BaseHTTPMiddleware` for any contextvars binding** — guaranteed to break PRIV-02 silently. Pure ASGI only.
- **Including `request.url.path` (raw path) in any metric label** — clip_id, segment_id, or any UUID in the URL → unbounded cardinality.
- **Calling `structlog.configure()` more than once** — replaces the processor chain; ordering bugs become invisible because the second call wins. Configure once at module import in `observability/__init__.py`.
- **Initializing Sentry inside a request handler** — must happen at module import (or once in `lifespan` startup). Otherwise Sentry misses errors that occur during DB init / pre-warm.
- **`logging.basicConfig` AFTER stdlib loggers were already created** — basicConfig is a no-op if any handler is attached to the root logger. Our dictConfig replaces basicConfig entirely; the `disable_existing_loggers=False` flag preserves the existing 12 module-level `logging.getLogger(__name__)` references but rewires their handler chain.
- **Forgetting `merge_contextvars` in BOTH the structlog processor chain AND the `foreign_pre_chain` of `ProcessorFormatter`** — D-02 is non-negotiable; without it, stdlib bridged logs miss `request_id`/`session_hash`/`clip_id`.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| JSON log formatter | Custom `logging.Formatter` subclass that calls `json.dumps(record.__dict__)` | `structlog.stdlib.ProcessorFormatter` + `structlog.processors.JSONRenderer` | Handles `exc_info` → structured traceback, contextvars merge, processor chain reuse, ISO timestamps, level lowercase normalization, and the gnarly `_record` / `_from_structlog` metadata stripping. |
| Stdlib → JSON bridge | Conditional `isinstance(handler, MyFormatter)` checks scattered through callsites | `ProcessorFormatter.wrap_for_formatter` (terminal processor on the structlog side) + `foreign_pre_chain` (on the formatter side) | Two ends of the bridge — `wrap_for_formatter` ensures structlog events arrive at the formatter as a dict; `foreign_pre_chain` ensures stdlib `logging` events also become a dict before the shared processors run. |
| Sentry PII scrubber | One-off `event.pop("session_uuid")` checks | List-driven recursive walker over `event` dicts/lists, comparing leaf keys against `REDACT_KEYS` set | (a) Sentry events are deeply nested (`event["request"]["data"]["session_uuid"]`, `event["extra"]["clip"]["gps_lat"]`, `event["breadcrumbs"][i]["data"][...]`); (b) D-14 says "list-driven recursive walker so adding fields is one-liner-cheap". |
| Request-ID middleware | UUID generation in every route | Single `RequestIDAndContextvarsBind` ASGI middleware | Centralizes ID generation, contextvars binding, and clearing in one place. Trying to do this per-route guarantees forgetting a route. |
| Prometheus exposition | Custom text-format renderer | `prometheus_client.generate_latest(REGISTRY)` + `CONTENT_TYPE_LATEST` | The text format is fiddly (escaping, `# HELP` / `# TYPE` headers, exemplar syntax). The library produces it correctly including OpenMetrics. |
| FastAPI route-template extractor | Regex over `request.url.path` | `request.scope.get("route").path` | Starlette already templated the route at routing time; just read it. |

**Key insight:** The observability domain is full of "I'll just throw together 20 lines" traps that turn into 200 lines when edge cases (deeply-nested Sentry events, exception traceback dictification, bridge processor ordering) surface. Use the libraries.

## Common Pitfalls

### Pitfall 1: BaseHTTPMiddleware Contextvars Isolation
**What goes wrong:** You write `class RequestIDMiddleware(BaseHTTPMiddleware)` and call `bind_contextvars(request_id=uuid4())` in `async def dispatch(self, request, call_next)`. Logs from inside route handlers DO NOT show `request_id`. Tests pass when you log inside `dispatch()` itself but fail when you log inside the route. PRIV-02 silently breaks.
**Why it happens:** Starlette's `BaseHTTPMiddleware` runs `dispatch()` in a sub-task spawned via an internal generator pattern; `contextvars.copy_context()` boundaries between the dispatch sub-task and the actual route-handler task mean contextvars set in the former are not visible in the latter. [CITED: starlette/middleware.md "BaseHTTPMiddleware > Limitations"; fastapi/fastapi#4696; Kludex/starlette#1081]
**How to avoid:** Use pure ASGI middleware (a class with `__init__(self, app)` + `async def __call__(self, scope, receive, send)`). The downstream `await app(scope, receive, send)` runs in the same Task as `__call__`, so contextvars bound before that line are visible to the route handler.
**Warning signs:** Tests where logs from `dispatch()` show the bind but logs from route handlers don't. Or `request_id` appearing only on the response-side log line, not the request-side.

### Pitfall 2: Processor Chain Ordering inside ProcessorFormatter
**What goes wrong:** Bridged stdlib logs come out missing `request_id`, or the `level` field is missing, or `exc_info` is rendered as a Python repr instead of a structured field.
**Why it happens:** `ProcessorFormatter` has TWO processor lists — `foreign_pre_chain` (runs on logs originating from stdlib `logging`) and `processors` (runs on the unified event-dict, both stdlib-bridged AND native-structlog). `merge_contextvars` belongs on BOTH paths if D-02 is to hold.
**How to avoid:**
1. The structlog-side `processors=` list ends with `ProcessorFormatter.wrap_for_formatter` (terminal — it stops the chain so `dictConfig` formatter takes over).
2. The `ProcessorFormatter.foreign_pre_chain=` includes `merge_contextvars`, `add_log_level`, `TimeStamper(fmt="iso")`, `format_exc_info` (or `dict_tracebacks`).
3. The `ProcessorFormatter.processors=` (the SHARED tail) starts with `ProcessorFormatter.remove_processors_meta` and ends with `JSONRenderer()` (or `ConsoleRenderer()` based on `LOG_FORMAT`).
4. The shared structlog processors (the ones in both chains) should be defined as a `shared_processors` list and reused.
**Warning signs:** Identical log calls produce different JSON shapes depending on whether the caller used `logging.getLogger(__name__).info("x")` vs `structlog.get_logger().info("x")`.

### Pitfall 3: Histograms Recreated Per-Request
**What goes wrong:** `ValueError: Duplicated timeseries in CollectorRegistry` on the second request.
**Why it happens:** `Histogram(name=...)` registers itself in the default `REGISTRY` at construction time. Defining inside a route handler or middleware `__call__` recreates the metric every call.
**How to avoid:** Define all metrics once at module import in `backend/observability/metrics.py`. Import and reuse.
**Warning signs:** First request to `/clips` works, second crashes the worker.

### Pitfall 4: `request.url.path` instead of `request.scope["route"].path`
**What goes wrong:** Prometheus cardinality explodes because every `clip_id`, `cluster_id`, and UUID becomes a distinct label value. After 10k uploads you have 10k distinct `route="/debug/clip/abc-..."` series.
**Why it happens:** Newcomer instinct says "use the request path"; FastAPI's templated path lives one level deeper in `request.scope["route"]`.
**How to avoid:** Always use `request.scope.get("route").path` for the label. Guard against `None` (no matched route → 404) by labeling such requests as `"<unmatched>"` or skipping the metric.
**Warning signs:** Prometheus dashboard shows thousands of distinct `route` label values where there should be ~10.

### Pitfall 5: `sentry_sdk.init(dsn="")` in Older Versions
**What goes wrong:** SDK either no-ops cleanly or raises a configuration error depending on version. OFFLINE_DEMO startup path crashes.
**Why it happens:** Behavior changed across SDK versions. In 2.x branch, `dsn=None` AND `dsn=""` are both no-ops. In 1.x, `dsn=""` was sometimes treated as "reach for env var SENTRY_DSN" or as malformed. [VERIFIED: sentry-python 2.x via Context7]
**How to avoid:** Explicit guard: `if SENTRY_DSN: sentry_sdk.init(dsn=SENTRY_DSN, ...)` — never call `init()` with an empty string. This is independent of which SDK version is pinned.
**Warning signs:** OFFLINE_DEMO startup logs an unexpected Sentry warning, or startup itself fails.

### Pitfall 6: Logger Init Order Bug
**What goes wrong:** First few log lines of the process (DB init, pre-warm log) appear as plain text; subsequent lines are JSON.
**Why it happens:** Some module imported at the top of `app.py` ran `logging.getLogger(__name__).info("...")` BEFORE our `dictConfig()` replaced root logger handlers. Stdlib `logging` had already attached the default StreamHandler from `basicConfig`.
**How to avoid:** `import backend.observability` (or `from .observability import configure_logging; configure_logging()`) MUST be the **first** import in `backend/app.py`, before `from . import config, db, events`. Inside `observability/__init__.py`, call `configure_logging()` and `init_sentry()` at module-import time, not lazily.
**Warning signs:** Mixed plain-text and JSON log lines on startup. The plain-text ones identify which module needs to be moved.

### Pitfall 7: structlog-bridged stdlib calls Lose `extra` Kwargs
**What goes wrong:** `log.info("msg", extra={"clip_id": "x"})` — the `clip_id` doesn't appear in the JSON output.
**Why it happens:** `LogRecord.extra` keys are not part of the event dict by default; `ProcessorFormatter.foreign_pre_chain` must include `structlog.stdlib.ExtraAdder()` for them to flow through.
**How to avoid:** Add `structlog.stdlib.ExtraAdder()` to `foreign_pre_chain`. Phase 8 has very few `extra=` callsites (most existing code uses `%`-format args), but Phase 9-13 will add `clip_id=` style calls — make sure ExtraAdder is in place now.
**Warning signs:** `extra=` kwargs silently dropped from output.

### Pitfall 8: Recursive Scrubber Mutating Dicts During Iteration
**What goes wrong:** `before_send_scrub` walks `event` and pops keys while iterating → `RuntimeError: dictionary changed size during iteration`.
**Why it happens:** Naïve recursive walker.
**How to avoid:** Iterate over `list(d.items())` or build a new dict. Same for lists — iterate by index.
**Warning signs:** Sentry events stop arriving and worker logs `RuntimeError` from inside `before_send`.

```python
# backend/observability/__init__.py
# Source pattern verified against: structlog 25.5.0 standard-library docs
# https://www.structlog.org/en/stable/standard-library.html
import logging.config
import structlog
from .. import config

def configure_logging() -> None:
    """Configure stdlib logging + structlog with shared processor chain.

    Both `logging.getLogger(__name__).info(...)` and `structlog.get_logger().info(...)`
    emit identical JSON (or console, in LOG_FORMAT=console mode) with merged contextvars.
    Idempotent — safe to call multiple times, but should be called exactly once
    at module import.
    """
    timestamper = structlog.processors.TimeStamper(fmt="iso", utc=True)

    # Shared processors run on BOTH stdlib-bridged AND native-structlog log entries.
    # ORDER MATTERS — merge_contextvars must run before the renderer.
    shared_processors = [
        structlog.contextvars.merge_contextvars,           # D-02 — pulls request_id/session_hash/clip_id
        structlog.stdlib.add_log_level,
        structlog.stdlib.add_logger_name,
        timestamper,
        structlog.processors.StackInfoRenderer(),
        structlog.processors.format_exc_info,              # exception → string in "exception" field
    ]

    # Renderer toggle (D-04, D-05) — read once at config time.
    renderer: object
    if config.LOG_FORMAT == "console":
        renderer = structlog.dev.ConsoleRenderer(colors=True)
    else:
        renderer = structlog.processors.JSONRenderer()

    # ---- structlog side: native structlog calls flow through this chain.
    structlog.configure(
        processors=[
            structlog.stdlib.filter_by_level,
            *shared_processors,
            # Terminal: hand off to the dictConfig formatter (which then runs the
            # ProcessorFormatter.processors chain below).
            structlog.stdlib.ProcessorFormatter.wrap_for_formatter,
        ],
        logger_factory=structlog.stdlib.LoggerFactory(),
        wrapper_class=structlog.stdlib.BoundLogger,
        cache_logger_on_first_use=True,
    )

    # ---- stdlib side: dictConfig with ProcessorFormatter as the formatter.
    logging.config.dictConfig({
        "version": 1,
        "disable_existing_loggers": False,    # critical — keeps existing 70 callsite refs alive
        "formatters": {
            "structlog": {
                "()": structlog.stdlib.ProcessorFormatter,
                # foreign_pre_chain runs on logs originating from stdlib logging
                # (i.e. the existing 70 callsites). It mirrors shared_processors so
                # bridged events have the same shape as native structlog events.
                "foreign_pre_chain": [
                    structlog.contextvars.merge_contextvars,
                    structlog.stdlib.add_log_level,
                    structlog.stdlib.add_logger_name,
                    structlog.stdlib.ExtraAdder(),       # Pitfall 7 fix
                    timestamper,
                    structlog.processors.format_exc_info,
                ],
                # processors runs on BOTH stdlib-bridged AND native-structlog events
                # after they unify into a common event_dict.
                "processors": [
                    structlog.stdlib.ProcessorFormatter.remove_processors_meta,
                    renderer,
                ],
            },
        },
        "handlers": {
            "default": {
                "level": "INFO",
                "class": "logging.StreamHandler",
                "formatter": "structlog",
            },
        },
        "loggers": {
            "": {
                "handlers": ["default"],
                "level": "INFO",
                "propagate": True,
            },
            # Quiet noisy third-party loggers down a notch (uvicorn.access is verbose).
            "uvicorn.access": {"level": "WARNING", "propagate": True},
        },
    })


def init_sentry() -> None:
    """Initialize Sentry if SENTRY_DSN is set; otherwise no-op (D-16).

    Called once at module import. Safe under OFFLINE_DEMO=true (skips entirely).
    """
    if not config.SENTRY_DSN:
        logging.getLogger(__name__).info("sentry skipped: SENTRY_DSN unset")
        return

    from .anonymity import before_send_scrub

        dsn=config.SENTRY_DSN,
        environment=config.SENTRY_ENVIRONMENT or "production",

        traces_sample_rate=0.0,                # D-13 — Logfire owns spans (Phase 13)
        send_default_pii=False,                # D-13
```

### §2. Anonymity Helpers + Sentry before_send Scrubber

```python
# backend/observability/anonymity.py
import hashlib
from typing import Any

# D-14 — extend list one-liner-cheap; Phase 11 will add e.g. "ip", "raw_address".
REDACT_KEYS: frozenset[str] = frozenset({
    "session_uuid",
    "gps_lat",
    "gps_lng",
    "blob_url",
})
REDACTED = "[REDACTED]"


def session_hash(session_uuid: str) -> str:
    """D-06: constant sha256 of session UUID. Pure function, no key, no rotation.
    Same input → same output forever. Used in log contextvars only (PRIV-02).
    """
    return hashlib.sha256(session_uuid.encode("utf-8")).hexdigest()


def _scrub(obj: Any) -> Any:
    """Recursively redact REDACT_KEYS from dict/list values.

    Returns a new structure (does not mutate in place during iteration — Pitfall 8).
    Leaves scalars unchanged. Handles dict, list, tuple, set; passes through everything else.
    """
    if isinstance(obj, dict):
        return {
            k: REDACTED if k in REDACT_KEYS else _scrub(v)
            for k, v in obj.items()
        }
    if isinstance(obj, list):
        return [_scrub(item) for item in obj]
    if isinstance(obj, tuple):
        return tuple(_scrub(item) for item in obj)
    if isinstance(obj, set):
        return {_scrub(item) for item in obj}
    return obj


def before_send_scrub(event: dict, hint: dict) -> dict:
    """Sentry before_send hook (D-14): walk the event dict and redact PII keys.

    Returning the event (possibly modified) lets it through; returning None drops it.
    We always return — we never want to drop legitimate errors.
    """
    return _scrub(event)
```

### §3. RequestIDAndContextvarsBind (Pure ASGI Middleware)

```python
# backend/observability/middleware.py
# CRITICAL: pure-ASGI, NOT BaseHTTPMiddleware. See Pitfall 1.
import uuid
from structlog.contextvars import bind_contextvars, clear_contextvars

from .anonymity import session_hash


class RequestIDAndContextvarsBind:
    """Pure ASGI middleware. Generates a server-side request_id and binds
    structlog contextvars (request_id, session_hash) for the duration of the request.

    PRIV-02 whitelist: only request_id, session_hash, clip_id ever bind.
    clip_id is bound later by the route handler (it doesn't exist yet at this layer).
    """

    def __init__(self, app):
        self.app = app

    async def __call__(self, scope, receive, send):
        if scope["type"] != "http":
            await self.app(scope, receive, send)
            return

        # D-11 — server-side UUID4. Never trust upstream X-Request-ID.
        request_id = uuid.uuid4().hex

        # Extract X-Session-Id header if present (anonymous session UUID from
        # iOS Safari localStorage). Hash it BEFORE binding (PRIV-02).
        session_uuid: str | None = None
        for name, value in scope.get("headers", []):
            if name == b"x-session-id":
                session_uuid = value.decode("latin-1").strip()
                break

        # Defensive clear — single-worker asyncio shouldn't leak across requests
        # but try/finally is the canonical structlog-contextvars pattern.
        clear_contextvars()
        bind_kwargs: dict = {"request_id": request_id}
        if session_uuid:
            bind_kwargs["session_hash"] = session_hash(session_uuid)
        bind_contextvars(**bind_kwargs)

        try:
            await self.app(scope, receive, send)
        finally:
            clear_contextvars()
```

### §4. XFFStrip (Pure ASGI Middleware)

```python
# backend/observability/middleware.py (continued)

# Headers to strip — PRIV-01 + defense in depth against alt header names.
# Lowercase bytes because ASGI headers are bytes-tuples in lowercase.
_FORBIDDEN_HEADERS: frozenset[bytes] = frozenset({
    b"x-forwarded-for",
    b"x-real-ip",
    b"forwarded",
    b"true-client-ip",
    b"cf-connecting-ip",         # Cloudflare leak vector if ever fronted
    b"x-client-ip",
})


class XFFStrip:
    """Pure ASGI middleware. Strips IP-revealing headers from scope BEFORE any
    downstream code (logging middleware, route handlers, Sentry capture) sees them.

    Must be the OUTERMOST middleware (added LAST in app.add_middleware order — D-12).
    """

    def __init__(self, app):
        self.app = app

    async def __call__(self, scope, receive, send):
        if scope["type"] == "http":
            scope = dict(scope)  # shallow copy — don't mutate the original
            scope["headers"] = [
                (name, value)
                for name, value in scope.get("headers", [])
                if name.lower() not in _FORBIDDEN_HEADERS
            ]
        await self.app(scope, receive, send)
```

```python
# backend/observability/metrics.py
from prometheus_client import (
    Counter, Histogram, CONTENT_TYPE_LATEST, generate_latest, REGISTRY,
)

# D-17 — bounded labels only. NO clip_id, NO session_hash, NO raw paths.

REQUEST_COUNT = Counter(
    "newz_http_requests_total",
    "Total HTTP requests",
    labelnames=("route", "method", "status_class"),
)

REQUEST_DURATION = Histogram(
    "newz_http_request_duration_seconds",
    "HTTP request duration in seconds",
    labelnames=("route", "method", "status_class"),
    # Default buckets are reasonable for a web API. Override only if Phase 13 needs.
)

STAGE_DURATION = Histogram(
    "newz_pipeline_stage_duration_seconds",
    "Pipeline stage duration in seconds",
    labelnames=("stage",),         # ingest|embed|cluster|compile|stitch
    buckets=(0.05, 0.1, 0.25, 0.5, 1.0, 2.5, 5.0, 10.0, 30.0, 60.0, 120.0, 300.0),
)


def _status_class(code: int) -> str:
    return f"{code // 100}xx"


class MetricsMiddleware:
    """Pure ASGI middleware. Records request count + duration per (route, method, status_class).
    """

    def __init__(self, app):
        self.app = app

    async def __call__(self, scope, receive, send):
        if scope["type"] != "http":
            await self.app(scope, receive, send)
            return

        import time
        start = time.perf_counter()
        status_holder: dict = {"code": 500}

        async def _send(message):
            if message["type"] == "http.response.start":
                status_holder["code"] = message["status"]
            await send(message)

        try:
            await self.app(scope, receive, _send)
        finally:
            elapsed = time.perf_counter() - start
            # Pitfall 4 — read templated route from scope, not raw path.
            route_obj = scope.get("route")
            route = getattr(route_obj, "path", "<unmatched>") if route_obj else "<unmatched>"
            method = scope.get("method", "UNKNOWN")
            status_class = _status_class(status_holder["code"])
            REQUEST_COUNT.labels(route=route, method=method, status_class=status_class).inc()
            REQUEST_DURATION.labels(route=route, method=method, status_class=status_class).observe(elapsed)


# /metrics route handler factory (D-09, D-10) — mirrors /admin/reset auth verbatim.
def make_metrics_endpoint(admin_token: str):
    from fastapi import Header, HTTPException, Response

    async def metrics(x_admin_token: str | None = Header(None, alias="X-Admin-Token")) -> Response:
        if not admin_token:
            raise HTTPException(status_code=503, detail="ADMIN_TOKEN not configured")
        if not x_admin_token or x_admin_token != admin_token:
            raise HTTPException(status_code=401, detail="invalid admin token")
        return Response(content=generate_latest(REGISTRY), media_type=CONTENT_TYPE_LATEST)

    return metrics
```

## Open Questions

1. **Test isolation for prometheus REGISTRY.**
   - What we know: `prometheus_client.REGISTRY` is a module-level singleton. Defining a new `Counter` with the same name in two tests raises `Duplicated timeseries`.
   - What's unclear: Whether the cleanest solution is (a) per-test `CollectorRegistry()` instances injected via a fixture, OR (b) reuse the global REGISTRY and accept that test ordering matters.
   - Recommendation: Plan to use option (a) — modify `metrics.py` to read a `REGISTRY` arg with default `prometheus_client.REGISTRY`, then test fixtures create a fresh `CollectorRegistry()`. Adds ~5 lines but unblocks parallel test runs cleanly.

2. **Should `STAGE_DURATION` for the `ingest` stage live inside the route handler or middleware?**
   - What we know: `embed`/`cluster`/`compile`/`stitch` have natural call boundaries inside `pipeline/run.py` and `pipeline/compile.py`.
   - What's unclear: `ingest` is roughly "everything in `POST /clips` before `asyncio.create_task(run_pipeline)`" — file write, DB insert, broadcast. Wrapping the whole route handler is a strange shape.
   - Recommendation: Wrap just `db.insert_clip(...)` since that's the bulk of ingest latency (file I/O + sqlite write). Document that `STAGE_DURATION{stage="ingest"}` measures DB-insert latency only; full request latency is captured by `REQUEST_DURATION{route="/clips"}`.

3. **Does `disable_existing_loggers=False` interact badly with uvicorn's own logger config?**
   - What we know: Uvicorn (`requirements.txt: uvicorn[standard]==0.32.1`) has its own logger setup it applies on startup via `--log-config` or defaults.
   - What's unclear: Order of operations — our `dictConfig` runs at `import backend.observability` (i.e. when uvicorn imports `backend.app:app`). Uvicorn's own logger config runs before that during uvicorn startup. So uvicorn's loggers are configured first, then our dictConfig with `disable_existing_loggers=False` keeps them but redirects through our formatter via the root logger handler. This SHOULD work; uvicorn.access logs should appear as JSON.
   - Recommendation: Verify in a Phase 8 task — start uvicorn locally with `LOG_FORMAT=json`, hit `/health`, and confirm both `[INFO]   "GET /health HTTP/1.1" 200` becomes a JSON line. If it doesn't, add `"uvicorn": {"handlers": ["default"], "level": "INFO", "propagate": False}` and `"uvicorn.access": {...}` explicit entries to the dictConfig.

4. **Does `sentry-sdk[fastapi]` 2.53.0 still respect `traces_sample_rate=0.0` such that no transaction events are sent at all?**
   - What we know: Per Sentry docs, `traces_sample_rate=0.0` disables performance tracing entirely; only error events are sent.
   - What's unclear: Some 2.x point releases have shipped subtle bugs around the auto-integration creating transactions even when sample rate is 0. Phase 13 will lock this with a regression test (OBS-08); Phase 8 just needs to set the value.
   - Recommendation: Set `traces_sample_rate=0.0` and document for Phase 13 that the regression test should `assert not any` outbound HTTP POST to Sentry's transactions endpoint during a sample request flow.
