# Phase 4.1: Compile Pipeline Overhaul — Context

**Gathered:** 2026-04-25
**Status:** Ready for planning
**Source:** Inline (spike 002 + design conversation 2026-04-25)

<domain>
## Phase Boundary

**In scope.** Make Phase 4 success criterion #1 ("total wall-clock to published segment is under 30 seconds") actually pass at runtime. Spike 002 measured the executed Phase 4 implementation at **112s** for the orchestrator chain alone — 94% of total compile time, ~4× the 30s SC, ~2× the 60s `asyncio.wait_for` safety cap. Spike 002 also showed the publisher subagent silently fails to invoke `save_segment` in 2/3 runs (Haiku returns a non-error `ResultMessage` without calling the tool), causing `_run_orchestrator_chain` to raise and `_save_fallback_segment` to silently replace the AI caption with the generic AP-wire string.

**Out of scope.**
- Embed optimizations — spike 001 says warm p50 = 2.5s, cold-start solved. Tail-latency hedging deferred until compile is fast.
- Sub-clip ingest segmentation (Marengo `embedding_scope=["clip"]`) — separate design; only relevant if we add cut-irrelevant-sections later.
- New product features — caption format, segment selection criteria, fallback caption text all stay as-is.
- OFFLINE_DEMO mode — Phase 5.
- Clustering, ingest, frontend feed rendering — untouched.
- New SC criteria — same Phase 4 SCs, just actually met at runtime.

**Demoable artifact.** Spike 002 bench (`.planning/spikes/002-compile-baseline/bench.py`) re-run against overhauled `compile.py` shows p50 < 15s, p95 < 30s, 0% publisher reliability failures across N=5+ runs.

</domain>

<decisions>
## Implementation Decisions

### Architecture (locked)

- **Genuine Python-level parallelism for caption-writer ‖ angle-selector** via `asyncio.gather` of two independent `query()` sessions, NOT prompt-instructed parallelism inside one orchestrator. Spike 002 proved that the existing `ORCHESTRATOR_PROMPT_TEMPLATE` instruction "Run angle-selector AND caption-writer IN PARALLEL" does not actually parallelize at runtime in `claude-agent-sdk==0.1.68` — the orchestrator chain ran sequential sonnet→sonnet→haiku for 112s. The fix is at the Python layer, not the prompt layer.
- **Editor subagent: removed.** Drop the `"editor"` entry from `compile.py:AGENTS`. The editor's job is to validate angle-selector's `clip_ids` ordering — empirically a no-op rubber-stamp that costs ~3–5s for ~zero quality gain. Angle-selector's output goes directly to publishing.
- **Publisher subagent: replaced with a Python function** `_publish_segment(cluster_id, ordered_clip_ids, caption, location)` that calls `db.insert_segment` directly. Drop `"publisher"` from `compile.py:AGENTS`. This eliminates the 1–3s Haiku roundtrip AND fixes the 67% silent-failure where Haiku reasoned successfully but skipped the `mcp__newz_tools__save_segment` tool call. A correctness bug, not just a performance bug.
- **Caption-writer stays as a direct `query()` call with vision content blocks** (`_run_caption_writer_with_vision`). The image-propagation workaround in `compile.py:13-18` is still needed — SDK 0.1.68 does not propagate MCP tool image returns into subagent vision context.
- **Angle-selector stays as-is** (sonnet subagent with `mcp__newz_tools__get_cluster_clips` + `mcp__newz_tools__get_clip_metadata`, ranks 2–4 clips by temporal spread, spatial diversity, duration ≥2s, no-redundancy 5s/10m). Same prompt, same tools — just invoked from a parallel `query()` session instead of inside the orchestrator chain.
- **Existing 60s `asyncio.wait_for` safety cap stays.** It becomes a true ultimate-fallback rather than the dominant constraint. `_save_fallback_segment` stays as the timeout/exception path.

### Surface area (locked)

- `compile.py` is the only production file that changes substantively. `run.py:_should_compile`, `compile_tools.py`, `db.py`, `events.py` are untouched.
- `compile.py:AGENTS` dict shrinks from 3 entries to 1 (angle-selector only). Editor and publisher AgentDefinitions are deleted, not commented out.
- `ORCHESTRATOR_PROMPT_TEMPLATE` is deleted (no orchestrator chain anymore). The new entrypoint is two `asyncio.gather`'d `query()` calls + one Python function.
- `compile_tools.py:save_segment` MCP tool is left in place (harmless, useful for debug; not invoked by the new compile path).

### Validation (locked)

- **Acceptance gate**: re-run `.planning/spikes/002-compile-baseline/bench.py -n 5` against the overhauled `compile.py`. Must show p50 < 15s, p95 < 30s, and 0/5 publisher failures (the publisher failure mode disappears by construction once the subagent is gone, but verify zero `_save_fallback_segment` invocations on healthy runs).
- Existing `backend/tests/test_compile.py` and `test_compile_timeout.py` must still pass. Tests asserting editor/publisher subagent presence MUST be updated to assert the new architecture (this is in scope, not a deferred breakage).
- Phase 4 VERIFICATION.md item #4 (CMP-04 runtime parallelism) was deferred to "human verification needed" — this phase closes that gap with the spike-bench numbers.

### Claude's Discretion

- Whether to split `compile.py` into multiple files (e.g., `_compile_caption.py` + `_compile_select.py`) or keep one file. Lean: keep one file unless it exceeds 400 lines.
- Naming of the new Python publisher function. Suggested: `_publish_segment`.
- Whether to drop the 60s `asyncio.wait_for` cap to 30s now that we expect to be well under it. Suggested: keep at 60s for the demo (safety > tightness).
- Internal structure of the parallel orchestrator: one `_run_compile_parallel(cluster_id)` function vs. inline `asyncio.gather` in `compile_segment`. Either is fine.
- Whether to commit the spike 002 bench re-run as a `.planning/spikes/002-compile-baseline/POST-OVERHAUL.md` follow-up or just include the numbers in the phase SUMMARY.md.

### Anti-patterns (do not do)

- **Do not** keep editor/publisher AgentDefinitions as commented-out dead code "for later." Delete.
- **Do not** add new ORCHESTRATOR_PROMPT_TEMPLATE-style prompt-level parallelism instructions. Spike 002 proved this doesn't work; the fix is at the Python layer.
- **Do not** introduce new MCP tools or agents. The whole point is to do less, faster.
- **Do not** change Phase 4 success criteria. We are meeting them, not redefining them.
- **Do not** scope-creep into embed optimizations, sub-clip ingest, or `clip_length` tuning. Those are deferred (see below).
- **Do not** modify clustering, run.py compile trigger, SSE event names, or feed rendering.

</decisions>

<deferred>
## Deferred Ideas

These came up in the design conversation but are explicitly out of scope for 4.1.

- **Embed compression to halve upload time** (spike 001 finding: upload = 54% of 2.5s embed). Worth ~1.4s. Trivial next to the 100s+ compile problem; revisit only if compile drops below 5s.
- **Marengo `embedding_scope=["clip"]` for sub-clip vectors** + sub-clip cutting at compile time. Real feature; needs its own phase. Not on the demo critical path.
- **Tail-latency hedging on Marengo embed** (spike 001 observed warm#1 = 12.9s, warm#2 = 4.6s — Marengo backend variance). Resilience pattern (e.g., 5s timeout + retry once) deferred until compile is fast.
- **`clip_length` parameter tuning** for finer-grained sub-clip embeddings. Coupled to sub-clip cutting feature.
- **Lower MediaRecorder bitrate on phone** to reduce upload time. UX-side; not on this phase's path.
- **Don't-await-postClip-on-submit** UX change to hide phone→backend upload latency. Frontend Phase, not compile phase.
- **Per-agent SSE progress events (CMP-07 partial gap from Phase 4 VERIFICATION).** With editor and publisher gone there are fewer "agents" to report on; revisit framing in a future phase.
- **Phase 4 VERIFICATION re-run** to upgrade items #4 (CMP-04) and partial #7 (CMP-07) to ✓ VERIFIED. This is bookkeeping that follows phase-4.1 verification, not part of phase-4.1 itself.

</deferred>
