<objective>
Refactor backend/pipeline/compile.py to replace the sequential 3-subagent orchestrator chain (caption-writer → angle-selector → editor → publisher) with genuine Python-level parallelism: caption-writer ‖ angle-selector via asyncio.gather of two independent query() sessions, followed by a Python _publish_segment function that calls db.insert_segment directly.

Purpose: Spike 002 measured the orchestrator chain at 112s p50 (~4× the 30s budget) plus 67% publisher silent-failure rate. The fix is at the Python layer — the prompt-level "run in parallel" instruction never actually parallelized in claude-agent-sdk==0.1.68. Removing the editor (empirically a no-op rubber stamp) and replacing the haiku publisher with a Python db.insert_segment call eliminates both the latency tax and the silent-failure mode by construction.

Output: A refactored compile.py with AGENTS dict deleted, ORCHESTRATOR_PROMPT_TEMPLATE deleted, _run_orchestrator_chain deleted, new _run_angle_selector + _publish_segment functions added, and _run_agents body changed to asyncio.gather.
</objective>
